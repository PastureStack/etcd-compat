# Compatibility Contract

The migration keeps these upstream surfaces stable:

- etcd v2 client and peer protocols;
- persisted data, WAL, snapshot, backup, and disaster-recovery formats;
- the `etcd` and `etcdctl` command names;
- standard client and peer ports, flags, environment variables, and configuration keys;
- metadata, certificate-action, service-index, and giddyup behavior required by the preserved control platform.

PastureStack names apply to maintained paths, documentation, image coordinates, and operator-facing messages. Historical environment aliases and host certificate paths remain accepted only as compatibility inputs.

Managed-service certificates must contain the `etcd.<stack>` DNS identity generated by the control platform. Health probes preserve that TLS server name while connecting to the selected container or local loopback endpoint; there is no insecure certificate-verification fallback.

Unix-domain v3 client endpoints keep the historical `unix://<socket>` contract, including socket filenames containing a colon. Endpoint parsing does not treat that filename suffix as a TCP port.

Before a release, validate single-member and multi-member operation, authenticated TLS, on-disk upgrade and rollback, mixed-version client access, snapshot restore, backup retention, lease and watch behavior, member replacement, and the Kubernetes control-plane lifecycle.
